1. PRÉSENTATION GÉNÉRALE
--------------------------------------------------------------------------------

unipath-api est le backend REST de la plateforme UniPath. Il gère l'authentification,
les concours universitaires (MESRS), le parcours académique (établissements privés),
les workflows de validation des dossiers, les notifications et la génération de PDF.

État actuel : MVP fonctionnel en environnement local (Laragon / MySQL / phpMyAdmin).
Migration récente depuis Supabase (PostgreSQL + Supabase Auth) vers MySQL + JWT local.


2. STACK TECHNIQUE
--------------------------------------------------------------------------------

  Composant          Technologie
  -----------------  ----------------------------------------------------------
  Runtime            Node.js (CommonJS)
  Framework HTTP     Express 5
  Base de données    MySQL via Prisma ORM 5
  Authentification   JWT (jsonwebtoken) + bcrypt (bcryptjs)
  Validation         Zod
  Upload fichiers    Multer → stockage local (uploads/dossiers-candidats/)
  Emails             Nodemailer + file d'attente EmailDelivery (node-cron)
  PDF                Scripts PHP (FPDF) invoqués depuis Node
  Tests              Jest + Supertest
  Logs               Winston

  Port par défaut    : 3001
  Préfixe API        : /api
  Health check       : GET /health


3. ARCHITECTURE
--------------------------------------------------------------------------------

  server.js                    Point d'entrée
  src/app.js                   Montage des routes Express
  src/routes/*.routes.js         Définition des endpoints par domaine
  src/controllers/*.js           Logique métier HTTP
  src/services/*.js              Services transverses (auth, email, PDF, fichiers)
  src/middleware/                JWT protect, rôles, upload
  prisma/schema.prisma           Schéma de données (30+ modèles)
  php/                           Génération PDF (fiche préinscription, convocation, relevé)
  scripts/                       Utilitaires (admins, migration, import SQL)
  uploads/                       Fichiers uploadés (dossiers candidats)


4. MODÈLE DE DONNÉES (PRINCIPAL)
--------------------------------------------------------------------------------

  AUTHENTIFICATION
    Compte          email, passwordHash, profilType, profilId
    ProfilType      CANDIDAT | COMMISSION | DGES | CONTROLEUR |
                    ADMIN_ETABLISSEMENT | ETABLISSEMENT

  UTILISATEURS
    Candidat        Profil étudiant/candidat (matricule, ANIP, série, etc.)
    MembreCommission  sousRole : MEMBRE | EXAMINATEUR | CONTROLEUR
    AdministrateurDGES
    Controleur      Profil contrôleur autonome (validation finale)
    AdminEtablissement  Lié à un Etablissement
    Etablissement   Peut aussi être un compte de connexion

  MODULE CONCOURS
    Concours        Libellé, dates, frais, séries acceptées, pièces requises (JSON)
    Inscription     Lien candidat ↔ concours (numéro d'inscription)
    DossierInscription  Workflow verdicts (examinateur → contrôleur → commission)

  MODULE PARCOURS ACADÉMIQUE
    Etablissement, Filiere
    CampagneInscription, CampagneFiliere
    Application, ApplicationDocument, Payment, Receipt
    PreinscriptionEtablissement, InscriptionAcademique, Note, Diplome

  TRANSVERSE
    Dossier         Pièces personnelles du candidat (acte, CNI, photo, relevé)
    Notification, EmailDelivery, ActionHistory, SystemAlert

6. FONCTIONNALITÉS PARTIELLES OU MANQUANTES
--------------------------------------------------------------------------------

  [ ] Paiement réel (gateway) — mock uniquement (MOCK_PROVIDER)
  [ ] Centres de composition — stockés en JSON sur Concours, API relationnelle supprimée
  [ ] Redis / WebSocket — configuration présente, non branchée
  [ ] Supabase — retiré du runtime ; scripts legacy restants
  [ ] Stockage cloud — migré vers disque local
  [ ] API notes / inscriptions académiques — auth sans contrôle de rôle strict
  [ ] Génération PDF — nécessite PHP + FPDF installés sur la machine
  [ ] Refresh token JWT — expiration → reconnexion obligatoire
  [ ] resend (package npm) — installé mais non utilisé


7. RÔLES ET PERMISSIONS
--------------------------------------------------------------------------------

  Rôle                  Capacités principales
  --------------------  -------------------------------------------------------
  CANDIDAT / ETUDIANT   Profil, dossier personnel, concours, parcours, applications
  COMMISSION (MEMBRE)   Revue dossiers, notes, statuts, notifications
  EXAMINATEUR           Premier verdict sur les dossiers
  CONTROLEUR (comm.)    Arbitrage, correction verdict examinateur, tableau de bord
  CONTROLEUR (profil)   Validation finale des décisions commission
  DGES                  CRUD concours, stats, gestion établissements
  ADMIN_ETABLISSEMENT   Campagnes d'inscription
  ETABLISSEMENT         Profil école, candidatures, préinscriptions, quittances

--------------------------------------------------------------------------------

  Obligatoires :
    DATABASE_URL=mysql://root:@localhost:3306/unipath
    JWT_SECRET=<clé secrète>

  Recommandées :
    PORT=3001
    FRONTEND_URL=http://localhost:5173
    APP_URL=http://localhost:3001
    JWT_EXPIRES_IN=7d
    ACADEMIC_YEAR=2025-2026
    SITE_CODE=UnP

    SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS
    EMAIL_QUEUE_ENABLED=false   (désactive le worker en dev)


11. MIGRATION RÉCENTE (ÉTAT ACTUEL)
--------------------------------------------------------------------------------

  Avant  : Supabase PostgreSQL + Supabase Auth + Supabase Storage
  Après  : MySQL local + JWT/bcrypt + stockage fichiers local

  Fichiers clés de migration :
    prisma/schema.prisma          provider = "mysql", modèle Compte
    src/services/auth.service.js  Auth JWT locale
    src/services/local-file-storage.service.js
    import_unipath_mysql.sql      Import données Supabase → MySQL
    comptes_connexion_unipath.txt Liste des identifiants

  Mot de passe import : UniPath2026! (tous les comptes migrés)


12. POINTS D'ATTENTION
--------------------------------------------------------------------------------

  - PHP doit être accessible pour la génération PDF
  - Les fichiers uploadés Supabase doivent être copiés manuellement dans uploads/
  - Ne pas commiter le fichier .env ni comptes_connexion_unipath.txt
  - prisma db push préféré aux migrations PostgreSQL archivées
  - Certains scripts (create-commission-sous-roles.js) référencent encore Supabase


13. CONCLUSION
--------------------------------------------------------------------------------

Le module API est opérationnel pour un MVP local couvrant les deux grands domaines
métier (Concours MESRS et Parcours académique). L'authentification et la persistance
sont entièrement locales. Les principales limites concernent les paiements réels,
le stockage cloud et quelques reliquats de l'ancienne stack Supabase.
